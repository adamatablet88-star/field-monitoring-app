# אפליקציית ניטור שטח — ייעוץ סביבתי

אפליקציה לאיסוף נתוני שטח עבור ייעוץ סביבתי: ניטור עדשת דלק, מערכות טיפול
(SVE / Bio-venting) ודיגום מי תהום.

## מבנה המאגר

Monorepo מבוסס npm workspaces:

```
packages/shared   מקור האמת היחיד למודל הנתונים (TypeScript), משותף ל-client ול-server
apps/server        Node.js + TypeScript + Express + Prisma (PostgreSQL)
apps/client        React + TypeScript + Vite, PWA, מסד מקומי (IndexedDB) דרך Dexie.js
```

### הרצה מקומית

```bash
npm install
npm run build:shared        # חובה לפני הרצת client/server — הם תלויים ב-dist הבנוי

# server
cp apps/server/.env.example apps/server/.env   # להגדיר DATABASE_URL אמיתי, JWT_SECRET, ופרטי מנהל ראשוני
cd apps/server && npx prisma migrate dev && npm run seed && cd ../..
npm run dev:server

# client (בטרמינל נפרד)
cp apps/client/.env.example apps/client/.env   # ברירת המחדל כבר מצביעה ל-localhost:3001
npm run dev:client
```

השרת חושף `/health`, `/auth/login` + `/auth/users`, ו-`/sync/push` +
`/sync/pull` (מוגן אימות, עם אכיפת RBAC — ראו `docs/architecture.md`).
הלקוח חוסם מאחורי מסך התחברות; לאחר כניסה יש ארבעה טאבים: "טפסי שטח"
(עדשת דלק, SVE, Bio-venting, דיגום מי תהום — בחירת אתר, ובאתר "משולב"
גם בחירת פרוטוקול; בכל אתר אפשר גם לעדכן סטטוס פעיל/לא-פעיל), "מה נדרש
החודש" (תצוגת תדירות/ביקור אחרון/סטטוס לכל אתר ומערכת, נגישה לשני
התפקידים), "דשבורד מגמות" (גרפים והשוואת קידוחים/מערכות, וייצוא Excel
לדוח רגולטורי לעדשת דלק — נגיש לשני התפקידים), ו-"הקמת אתר" (מנהל
בלבד — לקוחות/אתרים/קידוחים/מיכלים/מערכות טיפול/פרמטרים/קידוחי ניטור
מי תהום/משתמשים/תדירויות ודוחות
רגולטוריים). `npm run seed` (בתוך `apps/server`) יוצר את חשבון המנהל
הראשון לפי `SEED_ADMIN_USERNAME`/`SEED_ADMIN_PASSWORD` ב-`.env`.

## סביבת בדיקות בענן (חינם, בלי צורך בשרת משלכם)

כדי שהצוות יוכל להתחיל להשתמש באפליקציה מקישור אחד באינטרנט, בלי שאף
אחד צריך להתקין משהו במחשב שלו, מוכנות כאן שתי אפשרויות — **את שתיהן
צריך לחבר ל-GitHub ולתת להן להריץ את הקוד הזה, שתיהן חינמיות, ושתיהן
לא דורשות ידע טכני, רק לחיצות באתר.** ההבדל העיקרי: Netlify לא כולל
מסד נתונים משלו, אז צריך שירות נוסף (Neon) בשביל זה — שני חשבונות
חינמיים במקום אחד.

### אפשרות א׳: Netlify + Neon (מה שביקשתם)

Netlify יריץ את האתר עצמו; Neon (שירות נפרד, גם הוא חינמי) יחזיק את
מסד הנתונים. קודם מקימים את מסד הנתונים, ואז את האתר עם חיבור אליו.

**שלב 1 — מסד הנתונים ב-Neon:**

1. היכנסו ל-[neon.tech](https://neon.tech) והירשמו (אפשר עם GitHub).
2. יוצרים פרויקט חדש (**New Project**) — שם ואזור לא משנים, אפשר
   להשאיר ברירת מחדל.
3. Neon יציג מסך עם "פרטי חיבור" (**Connection Details**). מחפשים
   שם אפשרות בשם **Pooled connection** (חיבור מרוכז) ומעתיקים את
   המחרוזת שמוצגת שם (מתחילה ב-`postgresql://...`) — זה יהיה
   `DATABASE_URL` בשלב הבא. שומרים אותה בצד (למשל בהערת פתק).

**שלב 2 — האתר ב-Netlify:**

1. היכנסו ל-[netlify.com](https://netlify.com) והירשמו עם
   **"Sign up with GitHub"** (אותו חשבון שהמאגר `field-monitoring-app`
   נמצא בו).
2. **Add new project** ← **Import an existing project** ← מאשרים
   גישה ל-GitHub ← בוחרים את המאגר `field-monitoring-app`.
3. Netlify יזהה לבד את קובץ ה-`netlify.toml` וימלא את הגדרות הבנייה.
   ⚠️ אם מוצג שדה בשם **Base directory** (תיקיית בסיס) — יש
   להשאיר אותו **ריק** (לא לבחור אף תת-תיקייה כמו `apps/client` או
   `apps/server`). זו הנקודה היחידה שכדאי לשים לב אליה.
4. **לפני** הלחיצה על Deploy (או מיד אחריה, ואז לעשות דיפלוי מחדש):
   נכנסים ל-**Site configuration** ← **Environment variables** ←
   **Add a variable**, ומוסיפים ארבעה משתנים (כל אחד בנפרד):
   - `DATABASE_URL` — המחרוזת ששמרתם בצד משלב Neon.
   - `JWT_SECRET` — כל טקסט אקראי וארוך (אני יכול לתת לכם ערך מוכן
     בשיחה כאן אם תרצו — פשוט תבקשו).
   - `SEED_ADMIN_USERNAME` — למשל `admin`.
   - `SEED_ADMIN_PASSWORD` — סיסמה שתבחרו לחשבון המנהל הראשון (בשונה
     מ-Render, כאן אתם בוחרים אותה בעצמכם, כי אתם מקלידים אותה).
5. **Deploy site**. הבנייה הראשונה לוקחת כמה דקות.
6. אחרי שזה מסתיים, Netlify יראה כתובת (`https://....netlify.app`)
   — זו הכתובת לכל הצוות.
7. כניסה ראשונה: שם המשתמש והסיסמה שהגדרתם בשלב 4.
8. מומלץ מיד אחרי הכניסה הראשונה: "הקמת אתר" ← "משתמשים" ← ליצור
   שם משתמש נפרד לכל טכנאי אמיתי בצוות.

**חשוב לדעת**: את החלק הזה (Netlify + Neon) הכנתי בקפידה ובדקתי כמה
שיכולתי מקומית (כולל את הפונקציה שמריצה את ה-API עצמה), אבל לא הצלחתי
להריץ פה סימולציה מלאה של כל תהליך הבנייה בענן של Netlify עצמו — בניגוד
לאפשרות ב׳ למטה (Render) שבדקתי מקצה-לקצה בוודאות מלאה. יש סיכוי (לא
גדול, אבל אמיתי) שהניסיון הראשון ידרוש סיבוב תיקון אחד. **אם משהו לא
עובד — פשוט תעתיקו לי את הטקסט המדויק של השגיאה שמוצגת ב-Netlify
(בלוג הבנייה, "Deploy log"), ואני אתקן.**

### אפשרות ב׳: Render (הכל-באחד, נבדקה כאן במלואה)

Render כולל גם מסד נתונים וגם אתר באותו מקום, בלחיצה אחת, וקובץ
ההגדרה שלו ([`render.yaml`](render.yaml)) נבדק כאן באופן מלא (כולל
הרצה אמיתית מקומית שחיקתה בדיוק את מה ש-Render עושה) — לכן זו החלופה
הכי "בטוחה" אם באפשרות א׳ יהיה קושי.

1. [render.com](https://render.com) ← **Get Started** ← **"Sign up
   with GitHub"** (אותו חשבון GitHub).
2. **New +** ← **Blueprint** ← מאשרים גישה ← בוחרים את המאגר
   `field-monitoring-app`.
3. Render יזהה את `render.yaml` לבד ויציג מה הוא עומד ליצור (מסד
   נתונים אחד + אתר-שירות אחד, שניהם חינמיים) ← **Apply**.
4. אחרי כ-5–10 דקות ו-"Live" בירוק — לוחצים על שם השירות לראות את
   הכתובת (`https://...onrender.com`).
5. כניסה ראשונה: שם משתמש `admin`; הסיסמה נוצרה אוטומטית — בעמוד
   השירות ← **Environment** ← שורת `SEED_ADMIN_PASSWORD` ← סמל העין 👁.

### דברים שכדאי לדעת (מגבלות התוכניות החינמיות, שתי האפשרויות)

- **השירות "נרדם"** אחרי כ-15 דקות בלי שימוש, ולוקח כדקה "להתעורר"
  בפעם הבאה שמישהו נכנס — נורמלי, לא תקלה. מתאים מצוין לבדיקות; פחות
  נוח לשימוש יומיומי רציף (לזה יש תוכניות בתשלום שלא "נרדמות").
- **מסד הנתונים החינמי** (אצל Neon או אצל Render) לא נועד לאחסון קבוע
  לטווח ארוך — טוב לתקופת הבדיקות; כשתחליטו לעבור לשימוש אמיתי כדאי
  לשדרג לתוכנית בתשלום כדי לא לאבד נתונים. שווה לבדוק את התנאים
  המדויקים בעמודי התמחור כי הם משתנים מדי פעם.

   וההבחנה בין שם מערכת ב-SVE לעומת Bio-venting.

## סטטוס

כל 10 שלבי ה-roadmap המתוכננים הושלמו: שלד הפרויקט, סנכרון בסיסי
(outbox + push/pull עם זיהוי קונפליקטים מבוסס גרסאות) **ומנגנון פתרון
קונפליקטים מלא** (פאנל השוואה שדה-מול-שדה + שלוש פעולות הכרעה, בלי
דריסה שקטה), מסך הקמת אתר מלא, כל ארבעת מודולי טפסי השטח (עדשת דלק,
SVE, Bio-venting, דיגום מי תהום — כולל מנוע פרמטרים גמיש עם באנר סף
קריטי אוטומטי), התחברות אמיתית עם אכיפת RBAC בצד השרת (מנהל בונה מבנה
אתרים ומנהל משתמשים, טכנאי ממלא ביקורים ומעדכן קידוחים קיימים אך עורך
רק ביקורים שהוא עצמו יצר באותו יום — נאכף בשרת, לא רק ב-UI), ניהול
תדירויות ומעקב רגולטורי (תדירות ניטור עם Audit Trail, סטטוס פעיל/
לא-פעיל משני מקורות שנחתם בשרת, מעקב דוחות רגולטוריים, בדיקות מיוחדות
מתוזמנות, ומסך "מה נדרש החודש"), **ודשבורד מגמות + ייצוא Excel**: גרפי
מגמה אמיתיים (לא דמו) לכל אחד משלושת הפרוטוקולים עם השוואת קידוחים/
מערכות מרובים וטבלת סיכום רבעוני, וייצוא לדוח רגולטורי בפורמט Excel
מובנה בדיוק לפי מבנה הדוח האמיתי (עובי עדשה מודגש מעל 0.5 מ', סקימר
אקטיבי מקובץ לפי מיכל, נספח היסטוריה מלאה) — נטען lazy כדי לא לכבד את
שאר האפליקציה. כל הכתיבה עוברת דרך אותו מנגנון סנכרון offline-first.
נבדק מקצה-לקצה מול Postgres אמיתי בכל שלב — כולל תרחישי ריבוי-משתמשים
(שני "מכשירים" עצמאיים לבדיקת קונפליקטים; מנהל ואז טכנאי לבדיקת
תדירויות/סטטוס/דוחות) וניתוח ישיר של קובץ ה-Excel שהופק (לא רק "ההורדה
הצליחה"); תוך כדי הבדיקות נמצאו ותוקנו כמה באגים אמיתיים (sync
coalescing, תוויות שדות מתנגשות, שניים בפתרון קונפליקטים, אחד בסטטוס
פעיל/לא-פעיל, ואחד בכיווניות טקסט ה-SVG בגרפי המגמה — ראו
`docs/roadmap.md`). המשך פיתוח ייקבע לפי צורך בפועל.
